## Story

As the owner loading real shop files, when a feed carries the attributes of an engine oil, I want the import to read them by the spec's rules and keep them on the product, and I want the engine-oil product page to show them, so that a visitor can check the viscosity grade, volume, ACEA norm, oil type and manufacturer approvals the shops gave, and so that the category filters of #404 have stored, normalised values to stand on.

Today a feed has no way to say any of this: an oil's grade and norm live only in its title, which is never mined, and the product row has no place to keep them. A later row can write onto a stored product in only two ways, an empty category and an empty EAN, and a re-import never revisits the rest. After this story a feed can carry the five attributes of `aceite-de-motor`; the import reads each value strictly, stores the written form, counts what it could not read without printing it, keeps the first value and fills an absent one once from a later eligible row, with no new command; and the product page shows what is stored. A product outside `aceite-de-motor` shows nothing. A hand correction by the admin does not exist.

## Acceptance criteria

"A row" is a row of a feed `import-feeds` imports; a feed that is not approved is never imported (`CLAUDE.md`). "The five" are the five attributes of `aceite-de-motor` in the spec: viscosity grade, volume, ACEA norm, oil type and manufacturer approvals. "An entry" is whatever a feed uses to carry a value for one of the five; its names and path are the design pass's. "Reads" means the spec's rule for that attribute can read the value; "does not read" is the spec's *unparsed*, and the attribute is then absent. "Absent" is the state of an attribute no row has filled. "A blank" is an entry that is missing, empty or only whitespace. "Held" means stored on the product. "Marked" is as in US-12.2: the row comes from a collected feed, the product was created from one. "An eligible row" is a row whose feed is approved, whose shop is approved, whose offer is neither hidden nor in review, whose product is not hidden, and that is on the same side of the collected wall as the product (the S7.6 gate, D-2); it gates a later fill onto a stored product and not the row that creates the product (D-16, AC 30). "Public now" is as in US-2.4. Each AC ends with how it is checked; "integration" means the database-backed suite and "unit" the database-free one; where the design extracts a pure reader, the reading ACs are unit, otherwise integration. Examples are the spec's illustrative forms and are made up. Copy in these ACs is intent only.

What a feed can carry

1. A feed file, CSV or XML, plain or gzip, can carry an entry for each of the five. An import of such a file holds, on the product the row belongs to, the written form of each value that reads, when the fill rules of ACs 23 to 35 allow. Checked by integration, one CSV and one XML case.
2. A feed that carries no entry for any of the five imports as it does today: no row rejected, no attribute held, no new output line, and every feed file and fixture that exists before this story gives the same stored result and the same output. Checked by integration, the existing importer suites unchanged in what they assert about offers, products and output.
3. An entry never rejects a row, whatever it holds: a blank, a value that does not read, a value far outside its set or a very long one. The row's offer is stored as today and the row is not listed among the rejected. Checked by integration.
4. Anything a feed carries that is not one of the five is never held, never printed and never rejects the row. Checked by integration.
5. A value is read from the entry only. A row whose title or description names a grade, volume, norm, oil type or approval and whose entry is blank holds nothing for that attribute (spec rule 2). Checked by integration.

How each value is read (spec, *Normalisation rules*, as amended)

6. A viscosity value is read after trimming and ignoring case, with an optional leading `SAE`, and its two halves joined by a hyphen, an en dash, a slash, a space or nothing. It is held and shown as `<winter>W-<hot>`, upper-case W, one hyphen: `10w40` reads as `10W-40`, `SAE 15W 40` as `15W-40`, `0W/20` as `0W-20`. Checked by unit.
7. The viscosity closed set is the 44 pairings of the winter grades 0W, 5W, 10W, 15W, 20W and 25W with the hot grades 8, 12, 16, 20, 30, 40, 50 and 60, except 25W-8, 25W-12, 25W-16 and 25W-20 (D-5). Every one of the 44 reads; each of the four excluded does not. Checked by unit over all 48 pairings.
8. A viscosity value does not read when it is a winter half alone, a hot half alone, a pair outside the set, two grades in one cell, or other text; a monograde oil is therefore absent. Checked by unit.
9. A volume value is read as a number with an optional unit among `l`, `L`, `lt`, `lts`, `litro`, `litros`, `ml` and `cl`, in any case, with or without a space before the unit. A bare number is litres. `ml` and `cl` are converted to litres. It is held and shown in litres with a decimal comma, trailing zeros dropped, a space and a lower-case `l`: `4` and `4 L` read as `4 l`, `1,5 litros` as `1,5 l`, `500 ml` as `0,5 l`, `75 cl` as `0,75 l`. The value is exact to one millilitre and never passes through a binary float (`1005 ml` reads as `1,005 l`). Checked by unit.
10. A dot or a comma followed by one to three digits is the decimal separator; thousands separators are not accepted: `2.000` and `2,000` both read as `2 l`, and a value with both separators does not read. Checked by unit.
11. A volume is in range from 0,1 l to 220 l inclusive: `0,1`, `100 ml` and `220` read; `0,099`, `99 ml`, `0` and `220,001` do not. Checked by unit.
12. A volume value does not read when its unit is not in the list (a mass unit, a gallon, a ratio), when it is a pack form such as a count times a size, a range or two values, or other text. Checked by unit.
13. The ACEA closed set is twelve sequences: A1/B1, A3/B3, A3/B4, A5/B5, A7/B7 and C1, C2, C3, C4, C5, C6, C7 (D-3, D-4; the withdrawn A1/B1, A3/B3 and C1 stay readable because old stock still carries them). The A and B halves are one token and are never split: `A3` alone and `B4` alone do not read. The heavy-duty E sequences are not in the set. Checked by unit, each of the twelve alone, and `E4`, `E7`, `A3`, `B4` alone.
14. An ACEA value is read after an optional leading `ACEA`, in any case, as one or more sequences separated by a comma, a semicolon, a plus, the word `y`, or a slash between two C sequences, and a year suffix after a sequence is ignored: `ACEA C5` reads as C5, `A3/B4 + C2` as A3/B4 and C2, `C3-21` as C3, `c2/c3` as C2 and C3. Checked by unit.
15. A partial ACEA cell holds the sequences it recognised and drops the rest; each sequence is held once however often the cell names it; the order they are held and shown in is fixed and the design pass states it. A cell with no recognised sequence does not read. Checked by unit.
16. An oil type is read after folding case and accents, under the closed word list of D-15, Spanish and English: `sintético` or `synthetic` is synthetic, `semisintético`, `semi sintético`, `semi-synthetic` or `semi synthetic` is semi-synthetic, `mineral` is mineral (a value naming a family by one of those words, with or without the hyphen or a space where the list allows it); semi-synthetic is tested before synthetic; a leading `100%` or the word `base` is ignored. A value naming more than one family, naming none, or blank does not read. Checked by unit, one case per family and per refusal.
17. Manufacturer approvals are held as a list of short text items, as the feed wrote them and in order, after cleaning only: split on a comma or a semicolon (a slash or a space stays inside an item), each item trimmed with inner whitespace collapsed, blank items and case-insensitive duplicates dropped (the first spelling kept), at most 20 items kept, each at most 60 characters: an item of 60 characters is kept and one of 61 is dropped, not cut. Checked by unit.
18. A value that does not read is neither held nor shown anywhere, and the product keeps its category and its place in search. A blank is absent. Checked by integration, after an import of a row whose five entries all fail: no raw text in the stored product, the product page, the import output or the logs, and the product still found in its category and by the public search reader.

What the import counts (spec rule 10, D-7)

19. For a feed whose accepted rows carried values that did not read, the import output reports, for each of the five with at least one such value, how many accepted rows carried one, with no row text, no raw value, no product and no record number. The line's shape and its place among the indented lines are the design pass's (the `unknown_vehicles` and `fitment:` lines of S5.6 are the precedent). Checked by integration, on the formatted report.
20. A blank is not counted. An ACEA cell that held at least one recognised sequence is not counted. A feed whose values all read, or that carries no entry, prints output unchanged byte for byte. Checked by integration, on the formatted report, against a run that prints no such line.
21. Only accepted rows are counted: a row rejected for any existing reason never reaches the count. A known offer's row is counted as a new offer's row is, a collected row is counted like any other, and a value is counted whether or not the product already holds one for that attribute. Checked by integration.
22. The count never changes the exit code, which still means a feed failed and nothing else, and importing the same files again prints the same lines. Checked by integration, a run that prints the line, and a run that prints it and also has a failed feed.

Keeping and filling (spec rule 5; D-2, D-12)

23. An ordinary `import-feeds`, with no new command, argument, setting or migration step, gives a product an attribute it does not hold: the row that creates the product writes what it reads (AC 30), and an eligible row of its own that reads one fills it, on a new offer that joins the product and on a known offer. Products and offers stored before this story ships fill the same way on the next import. Checked by integration, with a product and an offer stored before the import runs.
24. A row that carries nothing, a blank or a value that does not read never blocks a later one: the first eligible row that reads fills the attribute, in the same import or in a later one. Checked by integration, both orders of two rows and across two imports.
25. A held attribute is never changed or cleared: not by a later row with another value, the same value, a blank or a value that does not read, not by a row of another feed, and not by hiding or unhiding the product, disabling the feed or shop, or an import that removes the offer. Checked by integration.
26. Attributes fill one by one: a product that holds a viscosity grade and no volume takes the volume of a later eligible row that reads, and its viscosity grade stays. Checked by integration.
27. A set value fills as a whole (D-12): a product that holds an ACEA set or an approvals list never gains, loses or reorders an item because a later row carries other or more items. Checked by integration, ACEA and approvals.
28. The category order: a product in `aceite-de-motor` holds the attributes of a row of its own that reads (the creating row, or an eligible later one, AC 30), whether its category was mapped before the first import or after it, and no more than one ordinary import after the category is mapped is needed; the first value held then stays. A product that is not in `aceite-de-motor` shows no attribute on its page under any order. Whether the import stores only for a product already in the category, or stores by the entry and the page shows only in the category, is the design pass's choice (D-2); either satisfies this AC, and the owner's guide states the order the owner follows. Checked by integration, a category mapped before the first import and a category mapped between two imports.
29. A fill changes nothing on the product except its attributes: not title, brand, part number, either normalised value, EAN, description, slug, category, hidden flag, collected marker or creation date. No offer is re-matched or moved, no product is merged, and the row's own offer is written as it is today. Checked by integration, the stored product row before and after compared column by column in every column but the attribute store.

The approval and hide gate (guardrail 1)

30. A row that joins a stored product, on a new offer, or sits on one, on a known offer, fills nothing when its feed is not approved, its shop is not approved, its offer is hidden, its offer is in review or its product is hidden, and the offer is stored or updated exactly as today. The row that creates a product writes the attributes it reads, as it writes the title and the EAN, whatever its shop's or feed's approval (D-16); the S7.6 eligibility gates only a later fill onto a stored product, and the hidden-product and in-review conditions apply where they can, to a later fill. When the condition clears the next import fills, and an unhide publishes nothing by itself. Guardrail 1 still holds through the public readers (AC 31). Checked by integration, one case per condition for a later fill, an import after the shop is approved, and a creating row of an unapproved shop that holds its attributes.
31. An attribute reaches a visitor only through a product that is public now. A product that is hidden, or whose offers all come from an unapproved feed or shop, has no public page and no attribute on any public surface. Checked by integration, the public product reader for a hidden product and for an unapproved-only product that holds attributes.

The collected wall (rule 6, decision 0017; US-12.2 kept)

32. A marked row fills a marked product it joined or already sits on, when otherwise eligible. Checked by integration, two collected feeds whose rows share a brand and part number.
33. A marked row that joins or sits on an unmarked product fills nothing, on the join and on every later import, and its offer joins as an offer only. The public product page of that product with the local flag off, and its public search results, are the same before and after the import. Checked by integration, the public product reader and the public search reader read before and after.
34. An unmarked row never gives a marked product an attribute, in either import order. Checked by integration.
35. With the local flag off, the attributes of a marked product appear on no public surface. The flag decides only what is shown, never whether a fill happens. Checked by integration, the same import with the flag on and off.

The product page

36. The product page of an engine-oil product shows each held attribute of the five as its own labelled line: viscosity grade, volume, ACEA norm, oil type and manufacturer approvals. Every label and every oil-type word comes from the es-ES message file and none is written inline (`CLAUDE.md` § Conventions). Where the lines sit is the ux pass's. Checked by integration through the product page reader and by unit on the rendered component, not through the browser.
37. An attribute the product does not hold draws no line, and a product that holds none draws no heading, block, placeholder or dash for them, as a null part number or EAN draws none today. Checked by unit and integration.
38. Values are shown as held: `10W-40`, `1,5 l`, `A3/B4, C2`, the oil type in the Spanish word of its family, and the approvals as plain text items; an item holding markup characters is shown as the literal characters and never as markup. Checked by unit, a rendered approvals item with markup characters.
39. A product outside `aceite-de-motor`, or in no category, shows no attribute line, whatever is stored. Checked by integration.
40. The rest of the page is as before: the part number and EAN details, description, offers, prices (integer cents in EUR, IVA included), shop order, fit block and structured data. Attributes are in no search result, no sitemap and no canonical. Checked by the existing product-page, structured-data and sitemap suites passing unchanged.

The admin has no edit (D-1)

## Notes for the human

- **The creating row writes its attributes, whatever its approval (D-16).** As the title and the EAN are, a product made by a row of a not-yet-approved shop holds that row's attributes, and the first value then stays (rule 5). Guardrail 1 holds because no unapproved offer is public and every public page goes through the shared visibility scope (AC 31). If an unapproved shop gave a wrong value first, the remedy is the same as for a wrong title: hide the product. Only a later fill onto a stored product is gated by the S7.6 eligibility (AC 30).
- **A wrong value cannot be fixed by hand.** The first value that reads stays and the admin has no edit (D-1). If a real feed gives a wrong value, the remedy is to hide the product, and a Backlog story for an admin "clear" is the next step.
- **A stored attribute outlives the feed that gave it.** Disabling a feed or shop never clears a held value (AC 25), as a product's title from the first feed stays today (0008). A product kept public by another shop keeps showing the first row's attributes. This is the same tension 0008 records for text.
- **A set never grows.** If a first feed gave an oil `A3/B4` and a second gave `A3/B4, C2`, the product keeps `A3/B4` (D-12).
- **A file edit now acts.** If the owner edits a file to add a readable value for an attribute a product does not hold, that product fills on the next import, under the same rules.
- **The grade set rests on secondary sources.** The J300 grades and the 44 pairings come from Wikipedia, TN Lab and Pakelo, not from a primary read of the paywalled standard (D-6). A closed-set change later is a one-line story.
- **Taken on trust, not opened by the drafting lane:** the code and test line numbers of `01-recon.md` (the drafting lane opened none of them; the design pass re-opens them); the evidence of `02-recon.md` behind D-3 to D-6 (not re-fetched); that decision 0006 rule 16 says 76 browser tests.
