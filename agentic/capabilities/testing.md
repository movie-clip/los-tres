## Running tests

Vitest 5 with two projects in `vitest.config.mts` (the package stays CommonJS; the config uses `import.meta.dirname`): `unit` (`tests/unit`, no database, no network) and `integration` (`tests/integration`, file-parallel, real PostgreSQL on the Compose `db` service, needs `npm run db:up`). Integration runs N workers, N = `integrationWorkers()` exported by `vitest.config.mts` (`INTEGRATION_WORKERS` from the process environment, not `.env`, else `min(8, cpus - 1)`; an invalid value throws), in `sequence.groupOrder: 1`, so Vitest numbers them `VITEST_POOL_ID` 1..N. `tests/support/global-setup.ts` drops every database `isIntegrationDatabase` names (`${DB_NAME}_tpl_test`, `${DB_NAME}_w<n>_test`, the old `${DB_NAME}_test`; never `startIsolatedApp`'s `${DB_NAME}_e2e_*`), migrates `${DB_NAME}_tpl_test` with `runMigrations` from `src/db/migrate.ts`, clones it one at a time to `${DB_NAME}_w<n>_test` for n = 1..`project.config.maxWorkers`, and `provide`s N as `integrationWorkers`; the clones stay after the run. After `runMigrations`, the setup copies `categories` and `vehicles` into schema `test_fixture` (`SNAPSHOT_SQL` in `tests/support/db.ts`); clones inherit it, and `public` never shows it. `tests/integration/reset-database.test.ts` pins the reset's post-state against the template's own state. `tests/support/test-database-env.ts` points `DATABASE_URL` at the worker's own clone and throws a named error for a missing or out-of-range pool id. Naming helpers live in `tests/support/env.ts` (unit tests: `test-database-names.test.ts`). Integration files call `resetDatabase()` (`tests/support/db.ts`) in `beforeEach` and `closeDb()` in `afterAll`. Playwright in `tests/e2e`, chromium only, against the Compose `app` at `E2E_BASE_URL` (default `http://127.0.0.1:${APP_PORT}`), no webServer, needs `npm run stack:up`. Commands: `npm run test:unit`, `test:integration`, `test` (both), `npm run check` (lint, typecheck, db:up, test: all of Vitest, no image build, no Playwright, budget 90 s; what a build lane verifies with, 0006 rule 8), `test:e2e`, `test:e2e:install`, and `npm run gate` = `npm run check`, then stack:up and test:e2e (`gate:ci` ends with `test:e2e:ci`). Env comes from `.env` via `process.loadEnvFile`. Helpers in `tests/support`, fixtures in `tests/fixtures`.

A third config, `vitest.timing.config.mts`, has one project `timing` over `tests/timing/**/*.timing.test.ts` (`maxWorkers: 1`, `fileParallelism: false`, the integration `globalSetup` and `setupFiles`, the alias imported from `vitest.config.mts` as `./vitest.config.mjs`). `npm run test:timing` runs it; no gate step does. `tests/unit/gate-determinism.test.ts` pins that over `vitest.config.mts` includes, the `package.json` scripts (walked through calls, `pre`/`post` hooks and install steps from the gate entries) and the text of `.github/workflows/*.yml`: `gate.yml`, and for `gate-repeat.yml` the `copy` job against the `gate` job (its steps equal, the checkout `ref` the one allowed difference, same settings and timeout), its trigger (`workflow_dispatch` only), no job named `gate`, a swallowed failure only in its `timing` job (plus one exact line in `plan`), `plan`'s `ref` output set only to empty or the checked merge commit and taken by every other job's checkout, `plan`'s `runs` and `pr` checks as whole-value bash matches (never `grep`) that end in an error and `exit 1`, top-level `permissions` of exactly `contents: read` with no secret, and the copy `strategy` (`fail-fast: false`, matrix from `plan`, no `max-parallel`). It reads text with no YAML parser, so an expression-built name, a YAML anchor, a reusable-workflow job or a script file a step calls is not seen: review covers them. It also pins the retry rule and the clock directive form (§ Shared scaffolding and gotchas, "Clock in tests"). It also pins `npm run check` (0006 rule 8): `steps()` expands it to lint, typecheck, db:up, test in order; nothing reached from it, hooks included, is stack:up, an e2e run, build, dev or text with `playwright` or `--build`; `scripts.test` is `vitest run`; gate and gate:ci expand to check's steps plus stack:up and test:e2e (:ci); each of the three is bare npm calls joined by `&&`. A change to the gate's step list (#363) updates those literals on purpose. It also pins the container separation (#361): every `tests/e2e` spec whose text matches `['"](run|rm)['"]`, `startIsolatedApp(` or `createAdminWithCommand(` is a stem in `CONTAINER_SPECS` of `playwright.config.ts` (or is catalogue-file-flow), and every stem is such a spec; the support files with a docker `run` or `rm` are exactly `admin-e2e.ts` and `isolated-app.ts`; the three project blocks keep their `testIgnore`, `testMatch`, `dependencies` and `workers: 1`, and the config has exactly two `workers:` keys. Its global setup drops every integration database and clones only `_w1_test`; the next integration run drops and rebuilds all of them, so no manual step is needed, but it must not run beside another Vitest run.

A config that must reuse `vitest.config.mts` imports it as `./vitest.config.mjs`: TypeScript maps it to the `.mts` file with no `allowImportingTsExtensions`, and Vite's config bundler resolves it. `vitest.config.mts` exports `alias` for that reason.

`CLAUDE.md` § Commands is the authority for the command list.

Integration run time no longer depends on the previous run: `resetDatabase` deletes rows instead of truncating, so it leaves no new relation files and the next run's first `drop database` forces a checkpoint of about 3 s (measured 2.8 s after a full run, 87 s with the TRUNCATE reset). `pg_stat_checkpointer.sync_time` shows it. A run right after another takes the same 40 to 50 s as one after idle.

`@layout` tag (D-6): a Playwright `describe` whose assertions depend on font metrics (heights, widths, tops, line counts, no-text-cut, same-row) is tagged `test.describe('name', { tag: '@layout' }, () => {...})`. CI runs `npm run gate:ci` (`test:e2e:ci`, `--grep-invert @layout`) on ubuntu-latest and skips them, because they are written against Windows system-ui metrics; the local `npm run gate` runs them. Functional specs stay untagged so CI still runs them. Write no new `@layout` test (0006 rule 11); the tag and `test:e2e:ci` stay until #339 removes them.

Playwright runs the projects another project depends on in full and ignores CLI filters for them, so `playwright.config.ts` reads the CLI `--grep-invert` (or `-gv`) itself (`cliGrepInvert()`) and passes it to projects `chromium` and `containers`, the dependencies of `catalogue-file`; without it `test:e2e:ci` would run every `@layout` test there. A new dependency project needs the same line. Only `--grep-invert` is mirrored: a CLI `--grep` is still ignored by `chromium` when it runs as a dependency (run one spec as in the S3.7 paragraph below, with `--no-deps`). `containers` and `catalogue-file` must hold no `@layout` test (`--grep @layout --list` shows 0 in both). `--list --project containers` without `--no-deps` also lists `chromium`, its dependency.

`vitest.config.mts` and `playwright.config.ts` must not import from `tests/`: tsconfig includes them, `next build` typechecks them in the image, and `.dockerignore` removes `tests/`. Put shared logic behind `setupFiles` or `globalSetup` instead (Playwright's takes a string path).

E2E data comes from Playwright `globalSetup` (`tests/e2e/global-setup.ts`), which runs `docker compose run --rm -T --no-deps app import-feeds` and throws a named message on `feeds=0` (quoted in `CLAUDE.md` § Commands). The e2e write rule is in § What must always be covered.

An e2e that hides or changes public data cannot do it on the Compose app: every spec reads the demo rows in parallel (a hidden demo product flakes root counts) and a row added to the dev database changes `admin-categories.spec.ts`'s `demoFingerprint` (hit in gate run 1). Use `startIsolatedApp` (`tests/support/isolated-app.ts`): a one-off container on a throwaway database, dropped in `afterAll`.

An e2e must never leave a feed approved: `import-feeds` reads every approved feed, so a transient approved e2e feed changes `entrypoint.spec.ts`'s `feeds=N` under `fullyParallel`. `admin-categories.spec.ts` keeps its fixed shop and feeds unapproved and proves the public side of guardrail 1 that way (a mapping on an unapproved feed publishes nothing); removal of an approved product is proved off the public readers in integration (importer-removal.test.ts, hide-public-sweep.test.ts); the one e2e removal test lives in catalogue-file-flow.spec.ts, which owns an approved feed, and cleanRows() deletes its replacement product.

S3.7 `catalogue-file-flow.spec.ts` is the one exception: it approves its own feed and runs in the Playwright project `catalogue-file`, which depends on `containers` (which depends on `chromium`), so no other spec runs beside it; it unapproves in the spec and `cleanRows()` in `beforeAll` and `afterAll`. A spec in a project with dependencies cannot be run alone by name: use `npx playwright test <file> --project catalogue-file --no-deps` (or `--project containers --no-deps`).

`legal.spec.ts` branches on the host `.env`: all four required `OWNER_*` values non-blank means 200 and values asserted as booleans (never printed), otherwise 500 and no brace in the visible text. To exercise the 200 branch without touching `.env`, export fake `OWNER_*` in the shell, run `docker compose up -d app`, run playwright with the same exports, then unset and run `docker compose up -d app` again.

Integration workers get fixed `AUTH_SECRET` and `SITE_URL` (`http://127.0.0.1:3000`) from `tests/support/test-database-env.ts`, so admin tests run without them in `.env`. Server components and actions are called directly with `next/headers` mocked: `vi.mock('next/headers', async () => (await import('../support/next-request')).nextHeadersModule)`; `startAdminRequest({cookie, origin})` sets the request, `nextRequest.cookieWrites` records every cookie the code under test would send, `redirectOf(fn)` returns the `NEXT_REDIRECT` target.

Actions in `src/app/admin` are tested by importing them with `next/headers` mocked and `next/cache` mocked as `{ revalidatePath: vi.fn() }`; without the second mock `revalidatePath` throws outside a Next request.

`e2e/admin.spec.ts` is serial and creates its admin with `docker compose run --rm -T --no-deps app create-admin` (stdin: email, then password; the fixed e2e admin is defined in that spec). A re-run ends that admin's sessions, so no other spec may use the account. It needs `AUTH_SECRET` and `SITE_URL` in the container: without them the sign-in answers unavailable and the spec throws a hint. To run it on an old `.env` without editing it: export `AUTH_SECRET` (32+ chars) and `SITE_URL=http://127.0.0.1:<APP_PORT>` in the shell, run `docker compose up -d --build --wait`, run playwright with the same exports, then `docker compose up -d app` in a clean shell.

E2E canonical, robots and sitemap checks read the `baseURL` origin, which equals `SITE_URL` in `.env` (the app container reads it); demo data makes the indexable side e2e-unreachable, so it lives in `integration/indexable.test.ts`.

The default host port is 3010 and may be taken, so never write a literal base URL: specs use the `baseURL` and `request` fixtures, and only `playwright.config.ts` computes it from `.env` (`appBaseUrl()` is gone).

Home e2e selects `home-panel`, `home-search[-input|-button|-notice]`, `home-all-link`, `home-all-count`, `category-tiles`, `category-tile[-link|-name|-count]` and `site-header-link`; the home count text is `icuPlural(messages.Home.productCount, n)`. Demo state is four tiles (the empty fuel category has none, in position order); the five-tile and one-tile states are unit renders (S11.3).

`search-privacy.spec.ts` is serial and shells out to docker: app logs, a one-off failing server (`docker run -d --network host` of the Compose app image, `PORT` from `unusedPort()`, `HOSTNAME=127.0.0.1`, `SITE_NAME` from `process.env`, `DATABASE_URL` to a closed port, removed in `finally`), and a `pg_dump --data-only` through `compose exec` on `db`.

Privacy assertions are contains/absent, never counts: the failing search logs its fixed code three times per request.

`playwright.config.ts` keeps trace and screenshot on failure; `gate.yml` and `gate-repeat.yml` upload `test-results/` for 7 days from an identical `if: failure()` step (#361).

A spec that creates or removes a container (`docker run`/`rm`, `startIsolatedApp`, `createAdminWithCommand`) is listed in `CONTAINER_SPECS` in `playwright.config.ts` and runs in project `containers` (one worker, after `chromium`): a container's start or stop changes a network interface and Chromium cancels the page loads waiting on a socket (`net::ERR_NETWORK_CHANGED`), so no browser test may load a page beside one (#361, 0006 rule 6). A failing server a browser test loads is started with `--network host`, which creates no interface. No retry, reload, sleep or longer timeout; `gate-determinism.test.ts` pins the list.

The Compose app image goes stale across branches: run `npm run stack:up` before iterating on e2e, or /buscar answers 404 from an old build. The same holds for a CSS mutation, or any `src` edit an e2e checks: it needs `npm run stack:up` to take effect, because the app image bakes the build; without it the pins pass against the old image.

A raw-HTML "value never appears" assertion must strip `<script>` blocks first: Next puts the request URL (query included) in the inline flight payload, so the typed `q` is in the raw response even though app code never renders it.

Listing e2e select only by the `data-testid` values of the design contract; the category name is read by `getByRole` heading level 1. Category pages are server pages: parse `request().get` HTML with `openRawHtml` for JS-off checks.

Category listing (S11.4): integration tests call `getPublicCategoryPage(slug, page, brand, sort)` and set `products.brandNormalised` and `partNumber` themselves (`insertListedProduct` sets neither; the local helper `listBranded` in `category-page.test.ts` does it). Canonical on `?marca=`/`?orden=` is proven by importing `generateMetadata` from `src/app/(public)/categoria/[slug]/page` in an integration test with `vi.mock('next-intl/server', () => ({ getTranslations: async () => (key) => key }))`; `SITE_URL` comes from `test-database-env.ts`.

A pin that sweeps every internal anchor on a product page must take `data-testid=vehicle-list-row` out and assert it as its own vehicle (category path, `coche` once, the only parameter): the tiles are the one link whose `coche` is not the selected car (`product-fit.spec.ts`).

The product e2e clicks nothing; the Referer click source is proven once in `go.spec.ts`, `product.spec.ts` asserts only that anchors are plain (no target, noreferrer, referrerpolicy, meta referrer).

Product JSON-LD e2e reads the raw `request.get` HTML with a regex over script tags (expect one match) and `JSON.parse`, then `openRawHtml` for the selector and the visible-price comparison; selector `script[type="application/ld+json"][data-testid="product-jsonld"]`.

The nested 404 (missing product, missing category, page or brand past the last) is a full server-rendered page: `src/proxy.ts` rewrites it to the root not-found. Assert the served body with `expectServerRenderedNotFound(html, siteName)` (`tests/support/page-checks.ts`), which strips `<script>` first; a `toContain` on the raw body passes on the flight payload and proves nothing. A Tab walk right after `goto` can lose the first Tab to hydration: wait for the button visible and `networkidle` before pressing.

A page-title or generateMetadata pin must run against the Compose image: Next dev and the production build differ on whether a not-found boundary's metadata replaces the page's, so a dev-server curl is not proof.

Expected site name and copy come from `SITE_NAME` in `.env` and `messages/es-ES.json`, never a literal. Raw server HTML is parsed by `page.setContent` in a context with `javaScriptEnabled: false`, not by an HTML parser dependency.

## What must always be covered

These are the guardrails' tests. A slice that touches a seam owes the
matching test, and it should be one that would fail if the rule broke:

- **(1)** No public read (search, category, product page, sitemap,
  `/go/<offer>`) returns an offer from an unapproved or disabled feed, a hidden
  product or offer, or a product waiting in the matching queue.
  - A removed offer (`offers.is_removed`) is on no public reader: `hide-public-sweep.test.ts` sets it with `setOfferRemoved` and asserts the same surfaces as a hidden offer; `seams.test.ts` fences the flag to `visibility.ts`, `src/db`, the seed and the importer.
  - A hidden product or offer is proved off every public reader by `tests/integration/hide-public-sweep.test.ts` through the real writer; its `view()` helper reads page, 404 rewrite, category, home tree, search, sitemap, `/go` and car filter in one call.
  - A product with `products.category_id` null is not public: assert it on the shared scope (`visibility.test.ts`), the product page, `/go` and the category page. `tests/unit/seams.test.ts` keeps the `isNotNull(products.categoryId)` condition in `src/server/visibility.ts` only.
- **(2)** The importer refuses a source that is not a registered feed.
- **(3)** An anonymous request cannot reach any admin route or server action.
  - Proven by `tests/integration/admin-routes.test.ts`: any page, layout or route handler under `src/app/admin` that answers anonymous with content fails, and every `'use server'` export in `src` must start with `requireAdminAction` plus `isAdminRefusal` except `signInAction` and `signOutAction`; a `'use server'` file outside `src/server/auth`, `src/app/admin` and `src/components/admin` fails.
  - `findUnguardedAdminRoutes` also calls the `generate*` exports of admin pages and layouts; entries look like `file#generateMetadata`; `admin/layout.tsx` is in `METADATA_ALLOWLIST` (static title, serves sign-in).
- **(4)** Feed prices parse to integer cents. Include a case where float
  parsing would round wrongly (for example `19.99`, `0.29`).
- **(5)** A `/go/<offer>` click row holds no IP, user agent or cookie, and the
  response sets no cookie.
  - Counting rules are proven in the integration project one rule at a time on an otherwise countable request.
  - The e2e cannot show a counted row because every e2e offer is a demo offer.
  - The privacy test spies on `console.*` and reads `row_to_json` of the click row.
  - Admin cookie rules: only `signInAction` writes a cookie (`nextRequest.cookieWrites` is empty for every refusal, guard call and expired cookie); `admin_sessions` `ip_address` and `user_agent` are null (`admin-storage.test.ts`); sentinel logs in `admin-logs.test.ts`; the public no-cookie e2e stays on public routes and `admin.spec.ts` asserts the one `admin.session_token` cookie.
- **Search (S5.4).** `seams.test.ts` pins that `search-page.ts` names no flag and has one `console.error`.
- **Matching (0008), slice B cut:** EAN attach, EAN with a different brand
  becomes its own product with reason `ean_brand_conflict` in `report.ownProducts`
  (since S7.1; not a reject), null brand on either side
  attaches, no EAN creates a product, invalid EAN rejected. Brand + part-number matching (S7.1) is covered by importer-brand-part-number.test.ts, matching-index.test.ts and the own-product describe.each in importer-matching.test.ts (AC map in the S7.1 run, 05-test.md); a conflict or ambiguity is an own product with a reason in report.ownProducts, never a reject; the queue is not built.
- **es-ES prices and seams.** Assertions on es-ES prices normalise U+00A0
  (`normaliseSpaces`, `tests/support/messages.ts`). `tests/unit/seams.test.ts`
  scans the source so the visibility flags, `fetch(`, `node:fs`, `@/db` in
  pages and `/ 100` stay out of places they do not belong.

- **Sitemap and robots seam.** `seams.test.ts` `isSitemapOrRobotsFile` covers metadata files, route handlers under `sitemap.xml/` and `sitemaps/`, and `src/server/catalogue/sitemap*.ts`, and asserts at least 5 files so it cannot go vacuous.

- **Fixture size.** A fixture-size change reaches literals outside `tests/fixtures/demo.ts` that a grep for the constant misses: `entrypoint.spec.ts` `feeds=2`, the page-count and page-length asserts, seed `approvedFeeds`. After changing the demo size grep tests for `feeds=`, `toHaveLength(1|2)`, `pageCount`, `[1, 2]` and `ROOT, 2`.

- **Count text.** A count-text guard must not substring-match (`/0 producto/` matches "50 productos"): anchor with `(^|\D)`, and escape query strings correctly in a template-literal RegExp.

- **Demo notice.** Any e2e that reads the first paragraph of `main` on a demo product or category page must skip `p[role=note]`.

Never call a live affiliate network in a test. Import from local fixture feed
files.

Any integration test or helper that writes to the database calls `assertTestDatabase()` (`tests/support/db.ts`) first, so it only ever writes this worker's own `${DB_NAME}_w<VITEST_POOL_ID>_test`; it refuses the template, another worker's database and any process without `VITEST_POOL_ID` (a throwaway bench that calls a helper sets `VITEST_POOL_ID=1` and names its database `<db>_w1_test`). e2e writes the Compose dev database through `import-feeds` in `globalSetup`, through `create-admin` (`createAdminWithCommand` in `tests/support/admin-e2e.ts`, and the spawns in `admin.spec.ts` and `admin-sources.spec.ts`) and through `psql` over `docker compose exec` on `db` (`psql` and `psqlScalar` in `admin-e2e.ts`, used by `admin-categories`, `admin-feeds` and `catalogue-file-flow`); `admin-products.spec.ts`, `collected-public.spec.ts` and `collected-admin.spec.ts` use a throwaway database (`startIsolatedApp`, S12.2). Admin specs sharing the dev database is accepted practice as long as the rows they write stay unapproved. A spec that hides or changes public data, or leaves a feed approved, must not do it there: it uses `startIsolatedApp`, or is the `catalogue-file` project exception; a spec that starts a container belongs in `containers` (§ Running tests).

Every public response is asserted to have no `Set-Cookie`; a browser visit also asserts `context.cookies()` is empty and no request leaves the app origin. The one exception is the `/go` click-through, which asserts the browser's request to the shop's `.example` host (§ Shared scaffolding and gotchas).

## Shared scaffolding and gotchas

- e2e global setup fails (`failed=1`) when the dev database holds an approved feed whose file is missing; no spec owns such a feed. Unapprove it for the run.
- `resetDatabase` needs a superuser (it sets `session_replication_role = replica` so rows can be deleted in any order); the Compose `db` user is one. A new public table is emptied with no change, but `dirtyEveryTable` in `reset-database.test.ts` must also write a row into it, or the non-vacuity check there fails by naming the table.
- `tests/support/catalogue.ts`: insert helpers whose defaults are the fully
  VISIBLE state, so a test sets only the one flag it is about. `insertProduct` defaults `categoryId` to a shared test category (`defaultCategoryId`, found by slug so it survives `resetDatabase`); pass `categoryId: null` for the unmapped state. `insertCategory({slug,name,parentId,position})`, `insertCategoryMapping` and `insertListedProduct` (a product with one visible offer per price) live in the same file.
- `tests/support/catalogue.ts` also has `vehicleIdBySlug(slug)`, `insertVehicle(partial)` (an extra active vehicle, position from 10000, retired by the next `runMigrations`, deleted by the next `resetDatabase`) and `insertFitment(productId, vehicleId, feedId)`. The `resetDatabase` snapshot holds the 50 vehicles with ids 1 to 50, so never assume an empty `vehicles` table.
- AC-to-test map for S5.5: unit `vehicle-catalogue-constant.test.ts`; integration `vehicle-catalogue.test.ts` (migrate and upsert), `vehicle-schema.test.ts` (constraints), `fit-state.test.ts` (query); `seams.test.ts` describe 'S5.5 vehicle fitment' pins `countedFitmentWhere` in `visibility.ts` and none of the flags in `fit-state.ts`.
- S5.6 import fitment: `csvOf` writes the `fitment` column only when some row defines `fitment`; `xmlOf` writes the element when defined; pass `fitment: ''` for an empty cell and leave it undefined for an absent column or element. Integration tests use real slugs from `VEHICLE_CATALOGUE` (never `insertVehicle`); `importer-fitments.test.ts` has `fitmentsOf(feedId)` (external id to sorted vehicle slugs); retire a vehicle with an update of `vehicles.isRetired`, `resetDatabase` restores it.
- AC 20 lives in `seams.test.ts` describe 'S5.5 vehicle fitment': fitments are written only in `src/server/importer/fitments.ts`; the non-vacuity test checks the regexes on in-memory violations.
- `fitments.created_at` is the database transaction time, not `importFeeds` `deps.now`; a delete-and-reinsert import would change it, which is what the AC 18 tests rely on.
- A rejected row's reject object has a field (`duplicate_id` carries `field: id`): use `toMatchObject` when a test is not about the field.
- `insertListedProduct({..., extra})` spreads any products column (partNumber, eanNormalised); search tests call `getPublicSearchPage(parseSearchTerm(raw), page)`.
- A migration over objects the test db already has: revert them inside `getDb().transaction`, insert legacy rows by raw SQL, re-run the file, assert, throw a sentinel to roll back (`search-migration.test.ts`).
- Pagination links render "Siguiente→": assert with `toContainText`, not `toHaveText`. A search e2e term is built with `encodeURIComponent`; hostile terms are written pre-encoded in the path.
- The header search box (T5.4.5, testids `header-search`, `header-search-input`, `header-search-button`) is on every public page except / and /buscar, where it is `display: none`.
